# 完整配置清单与已修复项

本文汇总 HP 15s-dy0xxx 黑苹果项目中**所有**已配置/已修复但容易遗漏的项目，作为 `疑难问题与修复记录.md` 的补充。

## A. 蓝牙系统层（NVRAM，最关键）

| 项目 | 值 | 说明 |
|---|---|---|
| `bluetoothInternalControllerInfo` | `00` × 14 字节（即 28 个 hex `0`） | **必须恰好 14 字节**。写成 13 字节会让 `bluetoothd` 以 `EXC_GUARD namespc 18 reason 2` 崩溃循环；写成 29 字节（把 28 个 hex 字符当 ASCII 解析）同样报 `CFDataGetLength(internalControllerInfoRef) != 14` |
| `bluetoothExternalDongleFailed` | `00` | 第三方蓝牙控制器被 `bluetoothd` 接受的必填项 |
| `csr-active-config` | `030a0000` | 部分关闭 SIP，kext 注入/加载必需 |
| `run-efi-updater` | `No` | 阻止固件更新写入 NVRAM |
| `SystemAudioVolume` | `46` | 开机音量 |

boot-args 相关：

| 参数 | 作用 |
|---|---|
| `-amfipassbeta` | AMFIPass，绕过 AMFI 校验以便注入未签名 kext |
| `-btlfxa2dpcheck` | BlueToolFixup 2.7.3 的 AirPods A2DP「连上但没声音」修复 |

### 为什么 14 字节这么关键

`bluetoothd` 在启动时读取 `bluetoothInternalControllerInfo` 来构造内部控制器对象。
长度必须是 `14`（6 字节地址 + 4 字节 class + 4 字节其它），否则直接 `EXC_GUARD` 崩溃，
表现为蓝牙图标反复闪烁、`bluetoothd` 反复重启。

> 写入方式：`NVRAM → Add → 7C436110-AB2A-4BBB-A880-FE41995C9F82 → bluetoothInternalControllerInfo`
> 用 `<data>` 类型，内容为 14 个 `0x00`。

## B. 背光与开机黑屏

**症状**：开机后内屏黑屏好几分钟才亮（系统其实已经启动完成，只是背光没点亮）。

**修复组合（DeviceProperties + boot-arg，缺一不可）**：

```
applbkl                        = 03000000
enable-backlight-registers-fix = 01000000
enable-hdmi-dividers-fix       = 01000000
boot-args += -igfxblr
```

| 项目 | 作用 |
|---|---|
| `applbkl` = `0x03000000` | 声明背光控制方式为 PCH PWM |
| `enable-backlight-registers-fix` | 修复背光寄存器写入路径（WEG 的 `-igfxblr` 等价开关） |
| `-igfxblr` | 开启上述修复 |
| `enable-hdmi-dividers-fix` | 修复 HDMI 高像素时钟下的分频死循环 |

## F. 事故教训与诊断方法论

### F1. `plutil -data` 命令行传 base64 会字节错位

**实测多次**：把 `00000800` / `01C7` 写成 `03000800` / `0107`，导致卡启动或黑屏。

**正确做法**：
- 用 Python `plistlib` 直接读写，或
- `plutil -replace <key> -xml '<data>BASE64</data>'`
- **每次改完必须解码并逐字段打印** `idx / bus / pipe / type / flags` 核对

### F2. `killall -HUP WindowServer` 会破坏显示枚举

现象：`IODisplayConnect = 0`、`system_profiler` 显示 0 个显示器，只能重启恢复。
**不要用信号去触发显示重探**。

### F3. boot-args 曾被写空

原因：脚本读取了过期的 `/tmp/cfg.xml`。
**每次改配置必须重新从目标文件读取当前值**。

### F4. Ubuntu Live 里 `test -s` 对 sysfs EDID 文件失准

`/sys/class/drm/*/edid` 的 `stat` 大小显示 0，但实际可读 128/256 字节。
必须用 `cat <file> | wc -c` 判断。

### F5. Lilu 插件日志在 macOS 26 不可见（重要修正）

**根因（两条叠加）**：

1. **Lilu 与插件都必须用 DEBUG 版编译，`DBGLOG` 才会保留**。
   `Lilu.kext 1.7.3` 官方 release 二进制约 531 KB，且二进制中 **`DBG` 字符串数为 0**
   → 这是 RELEASE 构建，`DBGLOG` 已被整段编译剔除。
   因此 **`-liludbg` / `-liludbgall` 对 RELEASE 版完全无效**（没有可输出的代码）。
2. **开机早期的 kext `IOLog` 会被内核日志环形缓冲冲掉**。
   实测：后期 AirPortRTW 的 365 条日志能留下，而早期插件的 `IOLog` 不出现。

**正确做法**：
- 要看到 Lilu/WEG 的调试日志：**Lilu DEBUG 版 + 插件 DEBUG 版 + `-liludbg`（或 `-liludbgall`）**
- 或者（本项目采用）：**把状态发布为 IORegistry 属性**，不依赖构建类型与日志缓冲，
  用 `ioreg -lw0 | grep -oE '"IBTP[A-Za-z]+" = <[^>]*>'` 读取

### F6. WEG DEBUG 的 `-igfxi2cdbg` 不能与 `disable-agdc` 同用

`kern_igfx_debug.cpp` L333-334 有 `PANIC("igfx", "igfxagdc=0 is not compatible with framebuffer debugging")`。
需要 `-igfxfbdbg` 时必须先移除 `disable-agdc`。

### F7. 启动问题必须加 `-v`

黑屏时无法判断卡在哪。`debug=0x100 keepsyms=1 -v` 是必备。

### F8. 恢复手段

```
Cmd+S 单用户模式
mount -uw /
mkdir -p /Volumes/ESP
mount_msdos /dev/disk0s1 /Volumes/ESP
cd /Volumes/ESP/EFI/OC
cp config.plist.bak-xxxx config.plist
reboot
```

## H. 其它已排除的坑

| 项目 | 结论 |
|---|---|
| `igfxonln` / `force-online` | 只改 `getDisplayStatus`，不改 `GetOnlineInfo`/EDID，单独用无效 |
| `AAPL0X,override-no-connect` | 只支持 **128 字节**（只用 base block，扩展块被忽略） |
| `STATUS 4803` | 蓝牙成功配对日志里也会出现，**不是故障** |
| `rtl8821c_config.bin` | 不是 LE 特性开关（只是 1 个寄存器写，offset 0xD9 = 0x0F） |
| `FBBoostPixelFrequencyLimit (0x100)` | 仅 Haswell 生效，CFL 上无效 |
| `-igfxmpc=600` | 数值不被解析，只认裸标志 |
